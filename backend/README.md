# Employee Directory: Backend API

A RESTful API built with **Laravel 13** and **MySQL** that powers the Employee Directory app. It provides create, read, update and delete operations for employee records, with server-side search, sorting and pagination.

## Features

- Full CRUD for employees through a JSON REST API
- Server-side search by name or email
- Sorting by name, email, role or date added
- Pagination with a configurable page size
- Request validation with unique email enforcement
- CORS configured for the React frontend
- Dockerized with Apache and PHP 8.4, with automatic migrations on startup

## Getting Started (Local)

```bash
# 1. Go to the backend folder
cd backend

# 2. Install PHP dependencies
composer install

# 3. Create your environment file
cp .env.example .env

# 4. Generate the application key
php artisan key:generate

# 5. Create the database (in MySQL)
#    CREATE DATABASE employee_directory;

# 6. Update the DB_* values in .env, then run migrations
php artisan migrate

# 7. Start the development server
php artisan serve
```

The API is available at **http://localhost:8000/api**.

The most important values in `.env`:

| Variable        | Description           | Local default                           |
| --------------- | --------------------- | --------------------------------------- |
| `APP_ENV`       | Environment name      | `local`                                 |
| `APP_DEBUG`     | Show detailed errors  | `true` (use `false` in production)      |

## API Reference

Base URL: `http://localhost:8000/api`

All requests should send `Accept: application/json` so validation errors return JSON instead of redirects.

| Method   | Endpoint          | Description                |
| -------- | ----------------- | -------------------------- |
| `GET`    | `/employees`      | List employees (paginated) |
| `POST`   | `/employees`      | Create an employee         |
| `PUT`    | `/employees/{id}` | Update an employee         |
| `DELETE` | `/employees/{id}` | Delete an employee         |

### List employees

`GET /api/employees`

| Query param | Type    | Rules                                          | Default      |
| ----------- | ------- | ---------------------------------------------- | ------------ |
| `search`    | string  | Optional, max 100 chars. Matches name or email | none         |
| `page`      | integer | Min 1                                          | `1`          |
| `per_page`  | integer | Min 5, max 100                                 | `10`         |
| `sort_by`   | string  | One of `name`, `email`, `role`, `created_at`   | `created_at` |
| `sort_dir`  | string  | One of `asc`, `desc`                           | `desc`       |

Example:

```bash
curl -H "Accept: application/json" \
  "http://localhost:8000/api/employees?search=priya&sort_by=name&sort_dir=asc&per_page=10"
```

Response `200 OK` (Laravel paginator):

```json
{
    "current_page": 1,
    "data": [
        {
            "id": 1,
            "name": "Priya Sharma",
            "email": "priya@company.com",
            "role": "Software Engineer",
            "created_at": "2026-01-15T09:30:00.000000Z",
            "updated_at": "2026-01-15T09:30:00.000000Z"
        }
    ],
    "first_page_url": "http://localhost:8000/api/employees?page=1",
    "from": 1,
    "last_page": 1,
    "last_page_url": "http://localhost:8000/api/employees?page=1",
    "links": [],
    "next_page_url": null,
    "path": "http://localhost:8000/api/employees",
    "per_page": 10,
    "prev_page_url": null,
    "to": 1,
    "total": 1
}
```

Results are ordered by the chosen column, then by `id` descending, so pagination stays stable when values tie.

### Create an employee

`POST /api/employees`

| Field   | Rules                                  |
| ------- | -------------------------------------- |
| `name`  | Required, string, max 255              |
| `email` | Required, valid email, max 255, unique |
| `role`  | Required, string, max 100              |

```bash
curl -X POST http://localhost:8000/api/employees \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"name":"Priya Sharma","email":"priya@company.com","role":"Software Engineer"}'
```

Response `201 Created` returns the new employee object.

### Update an employee

`PUT /api/employees/{id}`

Same fields and rules as create. The email must be unique, ignoring the employee being updated. Response `200 OK` returns the updated employee object.

### Delete an employee

`DELETE /api/employees/{id}`

Response `200 OK`:

```json
{
    "message": "Employee deleted successfully."
}
```

### Error responses

| Status | Meaning            |
| ------ | ------------------ |
| `404`  | Employee not found |
| `422`  | Validation failed  |
| `500`  | Server error       |

Validation error example (`422`):

```json
{
    "message": "The email has already been taken.",
    "errors": {
        "email": ["The email has already been taken."]
    }
}
```

## CORS

Allowed origins are defined in `config/cors.php`. The frontend dev server (`http://localhost:5173`) is allowed by default. If you run the frontend from Docker (`http://localhost:3000`) or deploy it elsewhere, add that origin to the `allowed_origins` array, otherwise the browser will block API requests.

## Docker

The `Dockerfile` is a multi-stage build: Composer installs production dependencies, then a PHP 8.4 Apache image serves the app from `public/`. On startup, `docker/entrypoint.sh` caches config and routes, runs migrations, and starts Apache.

Run the full stack (API, MySQL and frontend) from the repository root:

```bash
docker compose up --build -d
docker compose logs -f backend
```

The API is served at **http://localhost:8000/api**.

Useful commands:

```bash
# Open a shell in the backend container
docker compose exec backend bash

# Run migrations manually
docker compose exec backend php artisan migrate --force

# Stop everything
docker compose down

# Stop and delete the database volume (removes all data)
docker compose down -v
```

When running in Docker, set `DB_HOST=db` (the compose service name), not `127.0.0.1`. Docker reads `APP_KEY` and `DB_PASSWORD` from the root `.env` file used by `docker-compose.yml`.

## Troubleshooting

**`SQLSTATE[HY000] [2002] Connection refused`**
The database host is wrong. Use `127.0.0.1` locally and `db` inside Docker. Also check that MySQL is running.

**`No application encryption key has been specified`**
Run `php artisan key:generate`, or set `APP_KEY` in the root `.env` for Docker.

**CORS error in the browser**
Add the frontend origin to `allowed_origins` in `config/cors.php`.

**Config changes are ignored in Docker**
The entrypoint caches config at startup. Restart the container with `docker compose restart backend` after changing environment values.

**`entrypoint.sh: not found` on Windows**
Save `docker/entrypoint.sh` with LF line endings instead of CRLF.

## Known Limitations

- The API is currently **unauthenticated**. Anyone who can reach it can read and modify employees. Laravel Sanctum is installed, so token authentication can be added by wrapping the routes in `auth:sanctum`.
- There is no `GET /employees/{id}` endpoint, since the frontend lists and edits from the table.
